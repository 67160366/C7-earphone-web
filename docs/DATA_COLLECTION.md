# การเก็บข้อมูลดิบ (collect mode)

ใช้เก็บค่าดิบของเซ็นเซอร์ทั้ง 3 ตัวที่ 50 Hz ไว้ทำ data model ภายหลัง
- หูซ้าย BNO085 0x4A
- หูขวา BNO085 0x4B
- ต้นคอ MPU6050 0x68

หน้าเว็บคือ [`collect.html`](../collect.html) ข้อมูลจำลองเปิดได้ที่ `collect.html?demo`

ข้อมูลนี้ใช้พัฒนาแบบจำลองเท่านั้น ไม่ใช่การวินิจฉัยทางการแพทย์ และไม่ใช้กล้องในขั้นตอนใดเลย

## ภาพรวม
1. เฟิร์มแวร์เปิด USB ที่ **460800 baud** (เดิม 115200) ค่าดิบ 50 Hz ใช้แบนด์วิดท์ราว 9 KB/s ซึ่งเกือบเต็ม 115200
2. คำสั่ง `r` เข้าโหมดเก็บข้อมูล ส่วน `n` กลับโหมดปกติ (JSON v2 ที่ 5 Hz) ส่วน `z` / `i` / `s` ยังใช้ได้ทั้งสองโหมด
3. ระหว่างโหมดเก็บข้อมูล บอร์ดส่ง:
   - บรรทัด `D` ทุก 20 ms
   - บรรทัด `H` ตอนเข้าโหมดและทุก 5 วินาที
   - `[ESP-LOG] RATE ...` ทุก 1 วินาที
   - JSON v2 ทุก 1 วินาที เพื่อให้ปุ่มตั้งท่าเริ่มต้น (`calibration_id`) ยังทำงาน
4. ในโหมดนี้ BNO085 เปิด report 3 ชนิด ทุก 20 ms:
   - `0x28` ARVR rotation vector
   - `0x01` accelerometer
   - `0x02` calibrated gyro

   และปิด `0x05` / `0x08` ไม่ให้ quaternion ปนกันตาม [SENSOR_AXES.md](SENSOR_AXES.md) ข้อ 4
5. บัส I2C เปลี่ยนเป็น 400 kHz ระหว่างเก็บข้อมูล เพราะที่ 100 kHz อ่านไม่ทัน **ยังต้องตรวจกับสายจริง** ว่าไม่หลุด
6. MPU6050 ตั้ง DLPF ~44 Hz, accel ±2 g, gyro ±250 °/s และอ่าน 14 ไบต์ (accel + gyro) ทุก 20 ms

## รูปแบบบรรทัด (format 1)

### `H` (header)
```
H,format=1,boot_id=123,calibration_id=1,rate_hz=50,i2c_hz=400000,bno_q=14,bno_acc_q=8,bno_gyro_q=9,mpu_acc_lsb_g=16384,mpu_gyro_lsb_dps=131,left=1,right=1,c7=1
```
ถ้า `format` ไม่ตรงกับ `C7.Collect.FORMAT` หน้าเว็บจะเตือน ถ้าเปลี่ยนลำดับคอลัมน์ของ `D` ต้องเพิ่ม `COLLECT_FORMAT` ในเฟิร์มแวร์และ `FORMAT` ใน `assets/c7-collect.js` พร้อมกัน

### `D` (ค่าดิบ 1 จังหวะ)
```
D,seq,t_ms,flags, L_qw,L_qx,L_qy,L_qz,L_ax,L_ay,L_az,L_gx,L_gy,L_gz,L_acc, R_...(11 ค่า), C_ax,C_ay,C_az,C_gx,C_gy,C_gz
```
มีทั้งหมด 32 ช่องรวม `D` ทุกค่าเป็นจำนวนเต็มดิบ ตัวที่ไม่ fresh ส่งเป็นช่องว่างทั้งชุด

| ช่อง | ความหมาย |
| --- | --- |
| `seq` | ตัวนับ 16 บิต (วนรอบที่ 65536) ใช้นับบรรทัดที่หาย เริ่ม 0 ใหม่ทุกครั้งที่เข้าโหมด |
| `t_ms` | `millis()` ของ ESP32 |
| `flags` | bit0–2 = หูซ้าย / หูขวา / C7 fresh (ได้ค่าภายใน 500 ms), bit3–5 = มีค่าใหม่ตั้งแต่บรรทัดก่อน |
| `q` | quaternion w,x,y,z ของ report 0x28, Q14 (หาร 16384) |
| `a` (BNO) | accelerometer m/s², Q8 (หาร 256) รวมแรงโน้มถ่วง |
| `g` (BNO) | gyro rad/s, Q9 (หาร 512) |
| `acc` | ความแม่นยำของ rotation vector 0–3 (3 = ดีมาก) |
| `C_a` | MPU accel, 16384 LSB/g |
| `C_g` | MPU gyro, 131 LSB/(°/s) |

ถ้าบัสอ่านไม่ทัน บรรทัด `D` ยังออกทุก 20 ms โดยใช้ค่าล่าสุดซ้ำ ให้ดูจาก bit3–5 และ `RATE`

## ไฟล์ที่ได้จากหน้าเว็บ
กดดาวน์โหลดได้ 2 ไฟล์ ชื่อ `<รหัส>_s<รอบ>_<YYYYMMDD-HHMMSS>` ข้อมูลจำลองขึ้นต้นด้วย `SIM_`

### CSV (46 คอลัมน์)
| คอลัมน์ | หน่วย / ความหมาย |
| --- | --- |
| `t_host_ms` | ms นับจากกดเริ่มบันทึก (นาฬิกาเบราว์เซอร์) |
| `seq`, `t_dev_ms`, `flags` | ตามบรรทัด `D` |
| `label` | ป้ายท่าตอนนั้น (`transition` = ช่วงเปลี่ยนท่า, `free` = ไม่ได้อยู่ในขั้นตอน) |
| `step` | ลำดับขั้นในรายการท่า (ว่าง = ตั้งป้ายเอง) |
| `ref_angle_deg` | มุมอ้างอิงที่วัดด้วยมือ (ว่าง = ไม่ได้วัด) |
| `L_qw..L_qz` | quaternion หน่วย |
| `L_ax..L_az` | m/s² |
| `L_gx..L_gz` | °/s |
| `L_acc` | ความแม่นยำ 0–3 |
| `L_ex, L_ey, L_ez` | มุม Euler ตาม**แกนของชิป** (สูตรเดียวกับ `quaternionToEulerDeg()`) ยังไม่ใช่ก้ม/เอียง/หันของศีรษะ |
| `R_...` | แบบเดียวกับหูซ้าย |
| `C_ax..C_az`, `C_gx..C_gz` | MPU, m/s² และ °/s |
| `C_ex`, `C_ey` | มุมจาก accel: `atan2(ay, az)`, `atan2(ax, az)` (`C_ey` คือค่าเดียวกับ `mpu_tilt_raw`) |
| `C_ez_gyro` | gyro z ของ MPU รวมสะสมตั้งแต่เริ่มบันทึก **ลอยไปเรื่อย ๆ** ใช้ดูแนวโน้มสั้น ๆ เท่านั้น |
| `lr_deg` | มุมที่สองหูหมุนต่างกัน นับจากตอนตั้งท่าเริ่มต้น (ค่าสูง = หูฟังหลวม) |
| `simulated` | 1 = ข้อมูลจำลอง |

เก็บค่าดิบไว้ครบ จึงคำนวณ feature ใหม่ (เช่น tare แบบควอเทอร์เนียน หรือแปลงแกนชิปเป็นแกนศีรษะ) ภายหลังได้โดยไม่ต้องเก็บใหม่

### JSON (metadata)
เก็บข้อมูลเหล่านี้:
- ข้อมูล session (รหัส, รอบ, ตำแหน่งติดเซ็นเซอร์, หมายเหตุ)
- header `H` ล่าสุด, `boot_id` และ `calibration_id`
- รายการท่าที่ตั้งไว้ และช่วงเวลาจริงของแต่ละขั้น (`steps`)
- มุมอ้างอิงที่กรอก, จำนวนบรรทัดที่หาย, ชื่อคอลัมน์ และหน่วย

## โมเดล 3 มิติข้างกราฟ
ข้างกราฟใน `collect.html` มีโมเดลศีรษะ (ตัวเดียวกับหน้า dev, มุมมองด้านหน้า, แสดงแบบกระจก) ไว้ดูท่าทางคร่าว ๆ
- มุมที่ใช้คิดแบบเดียวกับเฟิร์มแวร์ทุกขั้น (`C7.Collect.firmwareHead()`):
  1. แปลง quaternion ของแต่ละหูเป็น Euler ตามแกนของชิป
  2. ลบค่าตอนกด "ตั้งท่าเริ่มต้น" (หรือตอนเริ่มส่งค่าดิบ)
  3. หาค่ากลางของสองหู
  4. ตัดค่าตามช่วงของ protocol
- tilt ใช้ `C_ey` ลบค่าตอนตั้งท่าเริ่มต้น
- หน้าเว็บไม่ได้สลับหรือกลับแกนให้ ถ้าโมเดลหันผิดทาง แปลว่าเฟิร์มแวร์ต้องแก้ตาม [SENSOR_AXES.md](SENSOR_AXES.md)
- ถ้าต้องการตรวจทิศทีละท่าแบบละเอียด ให้ใช้ "ตรวจทิศทางเซ็นเซอร์" ในหน้า dev
- ข้อมูลจำลองติดชิปแบบหันข้างเหมือนหูฟังจริง โมเดลในโหมด `?demo` จึงอาจหันไม่ตรงท่า

## วิธีเก็บข้อมูลที่แนะนำ

### ก่อนเริ่ม
1. ใส่หูฟังให้แน่น ติด MPU ที่ปุ่มกระดูก C7 ด้วยเทปให้ตำแหน่งเดิมทุกครั้ง และจดตำแหน่งในช่อง "ตำแหน่งติดเซ็นเซอร์"
2. กด "เริ่มส่งค่าดิบ" แล้วรอให้แผงสถานะขึ้น "สัญญาณพร้อมบันทึก" ซึ่งแปลว่า:
   - ทั้ง 3 ตัวได้ราว 50 Hz
   - บรรทัดหายน้อยกว่า 1%
   - ความแม่นยำ BNO 2 ขึ้นไป
3. ถ้าความแม่นยำต่ำ ให้หมุนศีรษะเป็นเลข 8 ช้า ๆ ราว 10 วินาที (รายการท่ามาตรฐานมีขั้น `calib_fig8` ให้แล้ว)
4. นั่งหลังตรง มองตรง แล้วกด "ตั้งท่าเริ่มต้น"
   - ค่าดิบไม่เปลี่ยน แต่ `lr_deg` และ JSON v2 จะนับจากท่านี้
   - จะ tare ใหม่ตอนวิเคราะห์ก็ได้

### ระหว่างเก็บ
1. ใช้ปุ่ม "เริ่มตามขั้นตอน" หน้าเว็บจะเริ่มบันทึก นับถอยหลัง และส่งเสียงทุกท่า
   - ระหว่างท่ามีช่วง `transition` (ค่าเริ่มต้น 3 วินาที) ตอนวิเคราะห์ให้ตัดช่วงนี้ หรือใช้เป็นข้อมูลการเคลื่อนไหว
2. ค้างท่าละ 20–30 วินาที ท่ามาตรฐาน:

| ป้าย | ท่า | ทำไม |
| --- | --- | --- |
| `neutral` | นั่งตรง มองตรง | ฐานอ้างอิง ทำซ้ำหลายครั้งระหว่างรอบ |
| `forward_head` | ยื่นคอไปหน้า ตามองจอ | คอยื่นแบบหัวตรง ซึ่งเซ็นเซอร์ที่หูอย่างเดียวจับยาก |
| `text_neck` | ก้มดูมือถือ | ก้มทั้งคอ |
| `desk_down` | ก้มดูโต๊ะ | ก้มหัวเป็นหลัก |
| `look_up` | เงยหน้า | ทิศตรงข้าม |
| `chin_tuck` | เก็บคาง | ทิศตรงข้ามของคอยื่น |
| `tilt_left` / `tilt_right` | เอียงหูลงหาไหล่ | roll |
| `turn_left` / `turn_right` | หันหน้า | yaw |
| `lean_back` | เอนหลังพิงเก้าอี้ | ลำตัวเอน คอไม่ยื่น |
| `trunk_forward` | โน้มตัวทั้งตัวไปหน้า คอตรง | ไว้แยกการเอนตัวออกจากคอยื่น (ปัญหาข้อ 4 ใน HANDOFF) |

3. **มุมอ้างอิง (ถ้าต้องการโมเดลประมาณ CVA):**
   - ระหว่างค้างท่า ให้อีกคนวัดมุมแนว C7 ถึงติ่งหูเทียบแนวนอน ด้วยไม้โปรแทรกเตอร์, goniometer หรือแอป inclinometer ในมือถือ (ใช้ accelerometer ไม่ใช่กล้อง)
   - กรอกตัวเลขแล้วกด "ใช้กับท่านี้"
   - ค่าจะติดเฉพาะแถวตั้งแต่ตอนกดจนจบท่านั้น
4. ถ้าทำท่าผิดหรือมีอะไรรบกวน ให้กด "ข้ามขั้นนี้" หรือตั้งป้ายเองด้วยปุ่มหรือคีย์ 1–9 แล้วจดในหมายเหตุ

### ต่อคนและต่อชุดข้อมูล
1. **ทำ 3 รอบต่อคน:**
   - กด "สลับลำดับ" ก่อนแต่ละรอบ ให้ลำดับท่าไม่เหมือนกัน
   - ถอดและใส่หูฟังใหม่ระหว่างรอบ ให้โมเดลเจอความต่างของการติดตั้ง
   - เปลี่ยน "รอบที่" ทุกครั้ง
2. **ช่วงใช้งานจริง:** หลังจบรอบ ให้ทำงานหน้าคอมตามปกติ 5–10 นาทีโดยไม่สั่งท่า (ป้าย `free`) ไว้ทดสอบว่าโมเดลใช้ได้นอกท่าที่สั่ง
3. **จำนวนคน:** ตั้งเป้าอย่างน้อย 8–10 คน ให้มีทั้งเพศ ส่วนสูง และทรงผมต่างกัน (ทรงผมมีผลกับการติดหูฟัง)
4. **แบ่ง train/test ตามคน** (leave-one-subject-out หรือ group k-fold)
   - ห้ามสุ่มแถวจากคนเดียวกันไปอยู่ทั้งสองชุด เพราะแถวที่ติดกันที่ 50 Hz แทบเหมือนกัน คะแนนจะสูงเกินจริง
5. **การเตรียม feature เบื้องต้น:**
   - ตัด `transition` และ 2 วินาทีแรกของแต่ละท่าออก
   - ตัดเป็นหน้าต่าง 1–2 วินาที (50–100 แถว) ซ้อนกันครึ่งหนึ่ง
   - ใช้ค่าเฉลี่ยและส่วนเบี่ยงเบนของ quaternion ที่ tare แล้ว, accel, gyro และมุม MPU

### ความเป็นส่วนตัวและการเก็บไฟล์
- ใช้รหัส (P01, P02, …) แทนชื่อ ตารางจับคู่รหัสกับชื่อเก็บแยกไว้นอก repo
- ไฟล์ข้อมูลอยู่ในเครื่องที่ดาวน์โหลดเท่านั้น หน้าเว็บไม่ส่งไปที่ไหน
- **ห้าม commit ไฟล์ข้อมูลเข้า git** ให้เก็บในโฟลเดอร์ `data/` (อยู่ใน `.gitignore` แล้ว)
- ขอความยินยอมจากผู้เข้าร่วมก่อนเก็บ และบอกว่าเป็นข้อมูลเพื่อพัฒนา ไม่ใช่การวินิจฉัย

## สิ่งที่ยังไม่ได้ตรวจกับบอร์ดจริง
ดูสถานะล่าสุดใน [HANDOFF.md](../HANDOFF.md) ตอนเขียนเอกสารนี้ยังไม่ได้ flash และยังไม่ได้ต่อเซ็นเซอร์ จึงยังไม่รู้ว่า:
- ได้ 50 Hz ครบทุก report ต่อหูหรือไม่ (ดู `[ESP-LOG] RATE`)
- I2C 400 kHz กับสายหูฟังจริงเสถียรหรือไม่ ถ้าไม่ ให้ลด `COLLECT_I2C_HZ` หรือ `COLLECT_REPORT_MS`
- 460800 baud กับชิป USB ของบอร์ดใช้ได้หรือไม่
