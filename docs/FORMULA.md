# สูตรมุมคอ (CVA) geometry 1

เอกสารนี้อธิบายว่าตัวเลข "มุมคอ" บนหน้าเว็บคิดจากอะไร ตัวแปรแต่ละตัวมาจากเซ็นเซอร์ไหน และค่าคงที่แต่ละตัวมาจากไหน
หน้า dev (`dev.html`) มีแผง "สูตรมุมคอ (CVA) ทีละขั้น" ที่แทนตัวเลขจริงลงในทุกบรรทัดด้านล่าง พร้อมภาพด้านข้างและโมเดล 3 มิติที่ขยับตามค่าเดียวกัน

> CVA ที่ได้เป็น **ค่าประมาณจากแบบจำลอง** เทียบกับท่าตอนตั้งศูนย์ ไม่ใช่การวัดด้วยภาพถ่าย และไม่ใช่การวินิจฉัยทางการแพทย์

## CVA คืออะไร
CVA (craniovertebral angle) คือมุมระหว่าง
- เส้นแนวราบที่ผ่านปุ่มกระดูกคอ C7 (ปุ่มที่นูนที่สุดตรงต้นคอด้านหลัง) กับ
- เส้นจาก C7 ไปติ่งหู (tragus)

มองจากด้านข้าง ยิ่งศีรษะยื่นไปข้างหน้า ติ่งหูยิ่งไปข้างหน้าและต่ำลงเทียบกับ C7 มุมจึงเล็กลง

## แบบจำลอง 2 ท่อนในระนาบด้านข้าง
ระบบพิกัด (หน่วย cm):
- จุดกำเนิดอยู่ที่ C7
- แกน z ชี้ไปข้างหน้า แกน y ชี้ขึ้น
- มุมบวกหมายถึงเอนไปข้างหน้าหรือก้ม (ตรงกับ `docs/SENSOR_AXES.md`)

```
ท่อน 1 (คอ):  C7 ──L──> C0          C0 = ข้อต่อหัวกับคอ (atlanto-occipital)
ท่อน 2 (หัว): C0 ──(t_z, t_y)──> T   T  = ติ่งหู หมุนไปกับกะโหลก

φ   = φ0 + g × tilt                    มุมแนวคอ C7→C0 วัดจากแนวดิ่ง
C0  = ( L·sin φ , L·cos φ )
h   = ( t_z·cos θ + t_y·sin θ ,  t_y·cos θ − t_z·sin θ )     θ = head_pitch
T   = C0 + h
CVA = atan2(T_y, T_z)
```

แต่ละท่อนรับข้อมูลจากเซ็นเซอร์คนละตัว ไม่ปนกัน:
- **ท่อนคอ** ขยับตาม `tilt` เท่านั้น
- **ท่อนหัว** ขยับตาม `head_pitch` เท่านั้น

## ตัวแปรที่วัดได้ (มาจากบอร์ด)
| ตัวแปร | มาจากไหน | ใช้ในสูตร |
| --- | --- | --- |
| `head_pitch` (θ) | BNO085 ที่หูซ้าย (0x4A) และขวา (0x4B) เฉลี่ยสองข้าง ลบค่าตอนตั้งศูนย์ บวก = ก้ม | หมุนติ่งหูรอบ C0 |
| `mpu_tilt` | MPU6050 ที่ต้นคอ (0x68): `atan2(ax, az)` ลบค่าตอนตั้งศูนย์ บวก = เอนไปข้างหน้า | `tilt` |
| `head_roll`, `head_yaw` | BNO085 | **ไม่เข้าสูตร** เพราะ CVA เป็นมุมด้านข้าง ใช้กับแถบเอียงและแถบหันหน้าเท่านั้น |

ถ้าไม่มี MPU (`mpu_tilt = null`, `tilt_estimated = true`):
- `tilt ≈ k × max(0, head_pitch)` เป็นการเดาว่าตอนก้มหน้าคอส่วนล่างงอตามด้วย
- คิดเฉพาะตอนก้ม และติดป้าย "ประมาณ"
- ในโหมดนี้จับคอยื่นที่หัวยังตั้งตรงไม่ได้

## ค่าคงที่และที่มา
| สัญลักษณ์ | ค่า | ชนิด | ที่มา |
| --- | --- | --- | --- |
| L | 12 cm | สมมติ | ระยะ C7 ถึง C0 ของผู้ใหญ่อยู่ในช่วง 10–13 cm (`base_plan.md` 4.3) |
| t_z | 1.0 cm | สมมติ | ติ่งหูอยู่หน้า C0 ประมาณ 1 cm |
| t_y | 2.0 cm | สมมติ | ติ่งหูอยู่สูงกว่า C0 ประมาณ 2 cm |
| g | 1.0 | สมมติ | แนวคอหมุนเท่ากับมุม MPU ที่เปลี่ยน |
| k | 0.5 | สมมติ | ใช้เมื่อไม่มี MPU |
| N | 52.05° | สมมติ | ค่าเฉลี่ยกลุ่มปกติใน `base_plan.md` ใช้เป็นท่าตั้งศูนย์ (กฎของโปรเจกต์) |
| φ0 | 40.058° | คำนวณ | แก้สมการด้านล่าง ไม่ได้ตั้งเอง |

ค่าที่ "สมมติ" ทุกตัวต้องปรับเทียบกับผู้ใส่จริง ดูหัวข้อ "ปรับเทียบ"

### φ0 มาจากไหน
ท่าตั้งศูนย์มี tilt = 0 และ θ = 0 และต้องได้ CVA = N พอดี:

```
atan2(L cos φ0 + t_y, L sin φ0 + t_z) = N
⇔ (L cos φ0 + t_y) cos N − (L sin φ0 + t_z) sin N = 0
⇔ L cos(φ0 + N) = t_z sin N − t_y cos N
⇔ φ0 = acos((t_z sin N − t_y cos N) / L) − N
     = acos((1.0 × 0.7884 − 2.0 × 0.6151) / 12) − 52.05
     = acos(−0.03682) − 52.05 = 92.110 − 52.05 = 40.058°
```

ตอนตั้งศูนย์:
- C0 = (7.723, 9.185) cm
- ติ่งหู T = (8.723, 11.185) cm
- ระยะ C7 ถึงติ่งหู = √(8.723² + 11.185²) ≈ 14.18 cm

## ทำไมต้องเลิกใช้สูตรเก่า (protocol v1)
สูตรเก่า: `c7 = −9 + ΔMPU + 0.35·pitch` แล้วเข้า `neckTilt = 4.2 + 1.02·c7 + max(0, 0.16·pitch)` พร้อมหมุนกะโหลกอีกรอบ

ปัญหา:
1. **pitch ถูกนับ 3 ครั้ง** และผสมเข้าไปในค่า C7 ทำให้สัญญาณคอยื่นหักล้างกันเอง
   - ตอนยื่นคอคนมักเงยหน้าสวนเพื่อให้ตายังมองตรง ซึ่งทำให้ pitch ติดลบ
   - ค่า C7 จึงลดลงแทนที่จะเพิ่ม
   - ตัวอย่าง: ยื่นคอ +10 แล้วเงยสวน −10 ได้ 50.46° (ท่าดี) และเงยสวน −15 ได้ 52.25° ซึ่งดีกว่าท่าปกติ
2. **เงยหน้า (pitch ติดลบ) ทำให้ CVA ดีขึ้นมาก** (+0.36°/° ถ้ามี MPU และ +0.49°/° ถ้าไม่มี) ตรงข้ามกับสิ่งที่เกิดตอนคอยื่นจริง
3. **roll และ yaw เปลี่ยนค่า CVA:** หัน 40° ทำให้ CVA ขึ้น 1.8°
4. **ค่าคงที่ไม่มีหน่วยและไม่มีที่มา** (4.2, 1.02, 0.985, 0.725, 0.2505) มาจากการจัดฉาก 3 มิติใน `live_test.html` เดิม

Protocol v2 ส่ง `mpu_tilt` แยกจาก `head_pitch`:
- ถ้าบอร์ดยังเป็น v1 และมี MPU หน้าเว็บจะถอดกลับเองด้วย `tilt = c7_angle + 9 − 0.35·pitch` แล้วติดป้าย "เฟิร์มแวร์ v1"
- ค่าที่ชนขอบ clamp เดิม (−15 ถึง 35) จะเพี้ยน

## โมเดล 3 มิติใช้สูตรนี้อย่างไร (`assets/neck-model.js`)
**ผิวและกระดูก:**
- หัวสแกนเป็น mesh ชิ้นเดียวแบบ skinned ไม่ตัดเป็นท่อน
- กระดูกเรียงเป็น `chest → c7 → c5 → c3 → C0` วางตามแนว C7→C0 ยาว L เอียง φ0

**วางสแกนให้ตรงกับสูตร:**
- หาจุด C7 (หลังคอระดับฐานคอ) และติ่งหูจากจุดยอดของสแกน
- หมุนสแกนรอบ C7 ให้เส้น C7→ติ่งหูอยู่ที่ 52.05° (หมุน +2.92° ดูได้ในหน้า dev)
- 1 cm ≈ 0.0759 หน่วยฉาก

**น้ำหนักผิว:**
- ผิวแต่ละจุดผูกกับกระดูกหลายชิ้นแบบไล่ค่าต่อเนื่อง (smoothstep กว้าง ±0.16 ของความยาวคอ)
- ใต้คางกับท้ายทอยค่อย ๆ เปลี่ยนไปตามหัว ผิวจึงยืดเหมือนกล้ามเนื้อ ไม่ขาดเป็น 2 ท่อน

**การหมุน:**
- การเปลี่ยนแนวคอ (φ − φ0) แบ่งให้ c7 / c5 / c3 เป็น 0.6 / 0.45 / 0.3 เพราะคอส่วนล่างงอมากกว่า
- แก้มุมของ c7 เล็กน้อยให้ C0 ไปอยู่ตรงที่สูตรคำนวณพอดี
- กระดูกหัวชดเชยให้กะโหลกหมุนเท่ากับ `head_pitch` ที่วัดได้

**เส้นวัดมุม:** เส้นและมุมบนโมเดลวาดจาก `cvaParts()` ชุดเดียวกับตัวเลขที่แสดง

## ข้อจำกัด
- ค่าคงที่ส่วนใหญ่เป็นค่าสมมติ ยังไม่ได้ปรับเทียบกับคนจริง
- MPU วัดเทียบแรงโน้มถ่วง เอนตัวทั้งตัวจึงทำให้ tilt ขึ้นด้วย ถ้าไม่มีเซ็นเซอร์ที่ลำตัวจะแยกเอนตัวกับคอยื่นไม่ได้
- **ตำแหน่ง MPU สำคัญมาก:**
  - การยื่นคองอคอช่วง C4–C7 เป็นหลัก
  - ถ้า MPU ติดต่ำไปทางหลังส่วนบน มันอาจหมุนน้อยจนจับไม่ได้
  - เรื่องนี้ยังเป็นสมมติฐาน ต้องทดสอบจริง
- `atan2(ax, az)` ของ MPU ใช้ accelerometer อย่างเดียว ไม่มี gyro หรือ filter จึงสั่นเมื่อมีการเคลื่อนไหวเร็ว และขึ้นกับทิศที่ติดบอร์ด
- ตั้งศูนย์แล้วจะได้ 52.05° เสมอ จึงวัด CVA จริงของแต่ละคนไม่ได้ วัดได้แค่การเปลี่ยนจากท่าตั้งศูนย์
